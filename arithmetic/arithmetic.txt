A continuación, detallo las reglas del manual y cómo adaptarlas al entorno online en Cursor para que la simulación sea exacta.
1. Dinámica de la Prueba según el Manual
• Punto de Inicio: Para todas las edades (16 a 90 años), se comienza con un ítem de práctica y luego se pasa al ítem 6. Si se sospecha de discapacidad intelectual, se empieza en el ítem 1.
• Regla de Secuencia Inversa: Si el usuario obtiene 0 puntos en los ítems 6 o 7, se deben administrar los ítems anteriores en orden inverso hasta obtener dos puntajes perfectos consecutivos.
• Criterio de Suspensión: La prueba se detiene tras 3 fracasos consecutivos (puntajes de 0).
• Control del Tiempo (Crucial): Cada ítem tiene un límite estricto de 30 segundos. El tiempo empieza a correr justo después de que el examinador termina de decir la última palabra de la instrucción.
• Regla de Repetición: El usuario puede pedir que se le repita el problema solo una vez por ítem. Importante: Al repetir el ítem, no se debe detener el cronómetro; el tiempo sigue corriendo desde la primera lectura.
• Prohibición de Apoyos: El evaluado no puede usar lápiz ni papel, pero el manual permite que use los dedos para "escribir" sobre la mesa como apoyo visual.
2. Adaptación para el entorno Online (Cursor/Javascript)
Para que tu página en Cursor sea lo más similar posible a un entorno real, debes programar la lógica siguiendo estos lineamientos técnicos:
A. Gestión de Estímulos Visuales y Auditivos
• Ítems 1 al 5: Dummy ejercicios.
• Ítems 6 al 22: Son estrictamente verbales. Al llegar al ítem 6, la UI debe ocultar cualquier imagen o texto del problema para obligar al usuario a procesar la información de forma auditiva, tal como en el test real.
B. Implementación del TTS y Timing
• El TTS (Text-to-Speech) debe ser el disparador del cronómetro. Usa el evento onend de la API de síntesis de voz para iniciar el contador de 30 segundos exactamente cuando termine la locución.
• Si el usuario presiona un botón de "Repetir", el TTS vuelve a leer el problema, pero el código debe asegurar que el contador global del ítem no se reinicie.
C. Procesamiento de la Respuesta (STT)
• Calificación: El manual establece que no es necesario que el usuario diga la unidad (por ejemplo, "manzanas" o "pesos"); si el número es correcto, se otorga 1 punto. Tu lógica de Javascript debe comparar solo el valor numérico capturado por el microfono.
• Respuestas tardías: Si el usuario responde correctamente pero después de los 30 segundos, el sistema debe marcar 0 puntos automáticamente.

Consideraciones para la programación en Cursor
1. Margen de Tiempo: Debes programar el sistema para que acepte la respuesta únicamente si se produce dentro de los 30 segundos posteriores al fin del audio (TTS).
2. Unidades de Medida: En los ítems donde la respuesta es tiempo (como el ítem 20), el manual acepta respuestas alternativas siempre que sean equivalentes (por ejemplo, 1 hora = 60 minutos).
3. Puntuación: Cada acierto dentro del tiempo límite otorga 1 punto; cualquier respuesta incorrecta o fuera de tiempo otorga 0 puntos.
4. Criterio de Suspensión: El sistema debe dejar de administrar la prueba automáticamente si el usuario comete 3 errores consecutivos (0 puntos).
Analogía para el desarrollo: Configurar estas respuestas en tu base de datos es como crear la "llave maestra" de una cerradura; no importa si el usuario usa una mano o la otra para girarla (si dice la unidad o no), lo único que importa es que los "dientes" de la llave (el número) encajen perfectamente en el tiempo exacto para abrir la puerta.
